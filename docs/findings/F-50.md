# F-50 — `divide` and `inv` keep 17 significant digits on PO and CPI

- **Assumption** (ADR-0005, division rule): a non-terminating quotient has scale
  max(18, scale(dividend) - scale(divisor) + 18), rounded half-down; a quotient below that scale is 0.
- **How it fails**: PO 7.5 and CPI give the same eight values for `obs-division` d1: 1/3 is
  `0.33333333333333333` (17 threes), 2.3333333333333333, 0.033333333333333333, and the tiny quotient
  `0.000000000000000000000033333333333333333` is not zero. Flottila gives 18 decimal places and 0 for that
  quotient. `obs-arithmetic` inv-001 agrees: PO and CPI give `0.33333333333333333` for inv of 3, Flottila
  `0.333333333333333333` (18).
- **Severity**: minor
- **Evidence**: `corpus/observations/obs-division/{po75,cpi}/d1-div-1.xml`, `meta.json`;
  `corpus/observations/obs-arithmetic/{po75,cpi}/inv-001-arith-inv.xml`; cases `fn/divide/001` (already
  `decided`) and `fn/inv/001`; #212 comment "Owner decisions (2026-11-13, second set)", point 2; ticket #221.
- **Change made**: none to behaviour (ADR-0005 stays for now). `fn/inv/001` is `decided`, expected output
  kept. The `divide` deviation text follows the observation: "Divides with a fixed number of decimal
  places (as in XPath), so a very small quotient can become 0. SAP PO keeps 17 significant digits." `inv`
  is `{level: "deviation"}`: "Keeps a fixed number of decimal places (as in XPath). SAP PO keeps 17
  significant digits."
