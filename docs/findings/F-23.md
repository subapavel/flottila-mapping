# F-23 — replaceValue never evaluated its value input (an F-22 break)

- **Assumption** (ADR-0006, F-22; since 614b550, 2026-11-04): every input of a box is evaluated
  before the call, so a data error in any input is raised at its box in both back ends.
- **How it fails**:
  - The runtime's `replaceValue` (ContextFamily) returned its replacement and never evaluated its
    value input.
  - With `divide(1, 0)` at that input, the runtime wrote output while Saxon-HE raised
    `err:FOAR0001` at the erroring box. The two back ends disagreed on whether the mapping fails.
  - The body dates from spec 2 (merge e302270). It became a defect when F-22 was adopted. The #70
    review fixed `if`, `and` and `or`, but missed `replaceValue`, which has no erroring branch of
    its own.
- **Severity**: major (the back ends disagree on failure).
- **Evidence**:
  - #86 `EveryInputDataErrorTest`, case `replaceValue input 1`: red at dacf007, green at fc27e9e.
  - GoldenCorpusTest 526/0 and DifferentialOracleTest 273/0 unchanged.
- **Change made**: the fix rides in #86 (fc27e9e): `replaceValue` evaluates its value input before
  returning the replacement. ADR-0006 is unchanged. The catalogue-driven sweep now guards every
  (function, input) pair, so a new function cannot repeat this.
