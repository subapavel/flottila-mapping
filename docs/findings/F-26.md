# F-26 — The tree scroll target (p95 ≤ 16.7 ms) sits at the measurement's floor

- **Assumption** (docs/GATE.md check 7, ADR-0013 "Performance"): the 20,128-field tree scenario has a p95
  frame time of ≤ 16.7 ms.
- **How it fails**: headless Chromium caps frames at 60 Hz, so one frame interval is 16.67 ms and the lowest
  p95 the scenario can show is one vsync. `requestAnimationFrame` timestamps jitter by about 0.1 ms, so a
  run with no dropped frame at p95 reads 16.7 or 16.8 ms by chance. A dropped frame reads 33.3 ms. The
  target as written cannot tell a smooth tree from a lucky run.
- **Severity**: minor (no dropped frame at p95 was observed; the gate verdict depends on rounding)
- **Evidence**: spec 5 gate on 7fb5576, three runs: p95 16.8, 16.8, 16.7 ms; max rows in DOM 32
  (`bench/RESULTS.md` "Spec 5 gate"). Before the editor tickets: 16.7 and 16.8 ms (#111, #114 hand-backs).
- **Change made**: none. GATE.md is the owner's; the owner question is #128. Proposed reading: "p95 below
  two vsyncs (< 33.3 ms), i.e. no dropped frame at p95", or "p95 ≤ 16.7 ms + 0.5 ms jitter".
