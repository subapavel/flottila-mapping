# F-3 — json-sKema needs no `--add-modules kotlin.stdlib` under Maven

- **Assumption** (ADR-0008 §Consequences, ADR-0014 §Consequences): on the module path
  json-sKema needs `--add-modules kotlin.stdlib`.
- **How it fails**: under maven-compiler 3.16.0 and surefire 3.6.1, an engine module that
  `requires json.sKema` (an automatic module, named from its file name) compiles and tests
  with no flag. Maven places kotlin-stdlib on the class path, and the automatic module reads it.
  Adding the flag breaks the build: javac says "module not found: kotlin.stdlib", and surefire
  throws `java.lang.module.FindException: Module kotlin.stdlib not found`. The earlier
  observation came from a hand-built module path where kotlin-stdlib sat on the module path.
- **Severity**: minor
- **Evidence**: grilling #13, scratch reactor (2026-10-30, not committed): `structure-import`
  with json-sKema 0.32.0 on JDK 25, `mvn -pl engine/structure-import -am verify` VERIFIED_PASS
  without the flag, EXECUTED_FAIL with it.
- **Change made**: ADR-0008 and ADR-0014 now say the flag is needed only on a hand-built module
  path and must not be set in the Maven build. Two things remain: javac warns about a
  filename-based automatic module (ADR-0017 exempts that one lint category in the modules that
  use json-sKema), and the name `json.sKema` changes if the library ever adds a module name.
