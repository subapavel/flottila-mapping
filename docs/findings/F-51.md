# F-51 — A constant fed into a context function is written into every Item

Status: closed (#230, 2026-11-14; spec #228). `removeContexts` over a single value is a generating
block, and `fn/removeContexts/004` is green on both back ends; ADR-0004 and ADR-0006 are amended
in the same merge.

- **Assumption** (ADR-0004:65): a constant fed into a context or queue function is a queue of one
  context with one value, so it reaches the first Item only.
- **How it fails**: `obs-lift-reuse` lift-4: PO 7.5 and CPI both write `W = k` in all three Items (V = 1
  only in Item 1, from `count`). PO's display queue shows the constant as a gray start row and a dark-gray
  terminal row, with no extra ordinary value.
- **Severity**: major
- **Evidence**: `corpus/observations/obs-lift-reuse/{po75,cpi}/l4-lift-4.xml`, `po75/lift-4-queues.txt`,
  `cpi/l4-lift-4-queue.txt`, `l4.xml`; #212 comment "Owner decisions (2026-11-13, second set)", point 3;
  ticket #230: red run `.logs/230-red.log` and green run `.logs/230-green1.log` of
  `t/230-f51-constant-lift` (`GoldenCorpusTest` `fn/removeContexts/004`,
  `RemoveContextsOfConstantAgreementTest`, `EngineFacadeTraceTest`, `FunctionBoxLoweringTest`).
- **Change made** (#230, the architect's approved design of 2026-11-14): the rule is keyed on
  `removeContexts`, whose result PO keeps in constant form (R1's display queue: `[k]` gray, `[k]`
  dark gray, no white value row), while `count` leaves it (N1: `<null>`, `[1]`, `[1]`;
  `fn/constant/006` stays green). `Lowering.generatingBlock` also holds for a `removeContexts` call
  whose input is an `AtomicToQueue`, a constant or another single value; the F-46 paths make its
  target field a generating `TargetRepeat` over the block. No change in the interpreter, `IrVerifier`
  or the export. Over a queue, over `copyValue`'s block and over `removeContexts` of a constant it
  stays a queue, as before (owner decision 1, not observed; #222). A single-value box that reads the
  block, such as `concat`, is refused with `unsupported-generating-input`, which PO accepts (owner
  decision 2), so `removeContexts`' fidelity is `deviation` ("Over a constant, its result cannot feed
  a box that takes a single value, such as concat. SAP PO accepts that graph."). ADR-0004 (the assumed
  reading) and ADR-0006 (Amendments, "Functions by execution kind", Consequences) state the rule;
  GLOSSARY "Generating block" names it.
