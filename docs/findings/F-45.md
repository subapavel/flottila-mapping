# F-45 — replaceValue replaces SUPPRESS, index numbers it, average of an empty context raises

Status: accepted (observation runs obs-statistic and obs-lift-reuse, PO 7.50 and CPI, 2026-11-11 to
2026-11-13; #212 groups G4 and G14). Fix ticket #216: `index` and `average` first, then `replaceValue`
as a context function (approved design, #216 comment of 2026-11-13; owner: fix now, class C).
ADR-0006 amended in the same ticket.

- **Assumption** (ADR-0006 l.50-51 and Consequences l.190-192; #75; `StatisticFunctions`,
  `StatisticFamily`, `statistic.xsl`, `ContextFamily.replaceValue`, `context.xsl`): SUPPRESS is no
  value. A `Lift` skips its body on SUPPRESS for every single-value function, `replaceValue`
  included, so SUPPRESS passes through it. `index` keeps a SUPPRESS slot without a number. `sum`,
  `average` and `count` do not read SUPPRESS. `average` of a context without a value gives an empty
  context, as XPath's `avg(())` does.
- **How it fails** (PO 7.50 and CPI agree on every case):
  - G4. `replaceValue` replaces the SUPPRESS too. In `fn/replaceValue/002` it writes three `All yes`
    where createIf gives `"", SUPPRESS, ""`. The display queues of R1 in sum-003 show input
    `["", SUPPRESS, ""] [SUPPRESS] [] [""]` and output `[5, 5, 5] [5] [] [5]`. An empty context stays
    empty. So the chains `fn/sum/003` (15, 5, 0, 5) and `fn/average/004` (5, 5, 5) never pass a
    SUPPRESS to `sum` or `average`. Those cases do not show how `sum` and `average` treat SUPPRESS
    (po75/average-004-...-check.txt says the same).
  - G4. `index` numbers a SUPPRESS slot as a value. In `fn/index/004`, input `"", SUPPRESS, "" |
    SUPPRESS, "" | ()` gives `1, 2, 3 | 1, 2 | ()`, and the display queue shows each SUPPRESS
    turned into a number.
  - G14. `average` over an empty context ends the run at `/Out/Item/V`. PO 7.50 raises
    `java.lang.ArithmeticException: Division undefined` in `flib7.Stat.average`. CPI raises
    `BehaviorInvocationException: Division undefined` in the same method. There is no output.
    CPI's meta.json reading label says "confirmed", but its output file shows the error.
  - The rule is not general to single-value functions. The obs-lift-reuse lift-2 display queues
    (po75/lift-2-queues.txt, cpi/l2-lift-2-queue.txt) show `toUpperCase` and `concat` passing
    SUPPRESS on and consuming the other input. `replaceValue` alone differs, which fits PO listing
    it under the node (context) functions.
- **Observed rule.** `replaceValue` gives its replacement at every slot, SUPPRESS included. Its
  contexts stay as they are, and an empty context stays empty. `index` numbers every slot of a
  context (or of the queue with reset never), SUPPRESS included. `average` of a context without a
  value is a data error at its box. `count` does not count SUPPRESS (fn/count/003, observed by #214).
- **Readings this rule adds, not observed:**
  - The error code is `err:FOAR0001`. ADR-0005 already uses it for division by zero, and the
    statistic family's other data errors already use W3C codes (`err:FORG0001`, F-44). A
    `po:<NAME>` code belongs to a context function's own conditions.
  - A context holding only SUPPRESS has no value either, so `average` raises there as well.
  - `sum` and `average` still skip SUPPRESS (no observation reaches them with one).
  - `counter` keeps SUPPRESS without a number, as `fn/counter/003` decided (F-43), so it no longer
    shares `index`'s numbering.
- **Severity**: major. The runtime and the export wrote output where PO and CPI fail the message,
  and they numbered and replaced differently from PO.
- **Evidence**:
  - `corpus/observations/obs-statistic/{po75,cpi}/`: `average-003-stat-average-error.txt`,
    `average-004-stat-average-suppress.xml` with `-check.txt`, `index-004-stat-index-suppress.xml`,
    `po75/index-004-stat-index-suppress-queue.txt`, `cpi/index-004-F1-queue.json`,
    `sum-003-stat-sum-suppress.xml`, `po75/sum-003-stat-sum-suppress-queue.txt`,
    `cpi/sum-003-R1-queue.json`.
  - `corpus/observations/obs-lift-reuse/{po75,cpi}/replaceValue-002-spec2-replace-value-create-if.xml`
    and `po75/lift-2-queues.txt`, `cpi/l2-lift-2-queue.txt`.
  - Cases `fn/replaceValue/002`, `fn/index/004`, `fn/sum/003`, `fn/average/003`, `fn/average/004`.
    Red before the fix: `.logs/216-oracle-red.log` on `t/216-statistic-suppress`.
- **Change made** (#216):
  - The five cases take the observed output or error and provenance `observed`. `fn/average/003`
    becomes an error case: `err:FOAR0001` at F1, replacing its expected.xml (ADR-0018 §Observed
    step 3).
  - `StatisticFunctions.index` numbers every slot, and the new `StatisticFunctions.counter` keeps the
    old numbering of values only. `StatisticFunctions.average` throws `ArithmeticException` at the
    first context without a value, and `StatisticFamily` raises it as `err:FOAR0001` at the box.
    `statistic.xsl` does the same: `po:statistic-numbers` takes `$suppress`, and `po:average` raises
    `err:FOAR0001`. No pinned helper block changes.
  - `index`, `average` and `sum` become `exact`.
  - `replaceValue` becomes a context function, the approved design's option (a). A `Lift` skips its
    body on SUPPRESS (`core.xsl` `po:lift`, `Lifting`), and `toUpperCase` and `concat` are observed
    doing so (lift-2), so the `Lift` stays as it is and only `replaceValue` leaves it. The catalogue
    gives it `executionKind` `context` and fidelity `exact`, as none of its cases is assumed.
    Lowering is unchanged: the box becomes a `FunCall`, and a single-value input enters it as
    `AtomicToQueue`. `ContextFunctions.replaceValue` gives the replacement at every slot and keeps
    the context starts; `ContextFamily` binds it as a queue function, and its single-value map is
    empty; `context.xsl` `po:replaceValue` takes and gives `array(item()*)`. Nothing changes in
    `engine/ir`, `core.xsl`, `Lifting`, `XsltExporter` or the catalogue schema.
  - `fn/replaceValue/002`, `fn/sum/003` and `fn/average/004` are green on both back ends.
    `fn/sortByKey/008` builds its key as `replaceValue(createIf(Tag), 5)`, which no longer holds a
    SUPPRESS: its expectation follows the observed rule (`decided`, its mapping unchanged, ADR-0018),
    and the new `fn/sortByKey/009` asks the old question with `concat(createIf(Tag), constant 5)`.
  - ADR-0006 amended: Status, `replaceValue` among the context functions because it reads SUPPRESS,
    the `Lift` SUPPRESS reading observed for `toUpperCase` and `concat` and assumed for the rest, and
    a Consequences bullet for `replaceValue`. GLOSSARY "Execution kind" and "Context function".
  - Paths the architect widened beyond the ticket's (approved design, as for #214 and #221):
    `engine/mapping/src/test/resources/pinned-71/function-catalogue.json` and the javadoc of
    `FunctionCatalogueTest.MAIN_CATALOGUE`, `XsltExporterTest.MAIN_HELPER_MODULE`'s javadoc (the
    `po:replaceValue` block of `pinned-71/po-runtime.xsl` is a ticket path), the tests rewritten to
    the observed rule outside engine/runtime and engine/xdm (`SuppressCatalogueEntriesTest`,
    `LiftLoweringTest`, `LiftExportTest`, `EngineFacadeTest`, `SuppressContextFunctionsAgreementTest`,
    `UntakenBranchDataErrorTest`), `corpus/cases/fn/sortByKey/{008,009}` and
    `corpus/mappings/sort-by-key-numeric-concat-suppress.mapping.json`, and `GLOSSARY.md`. Each
    pinned fixture re-pins the `replaceValue` entry or block alone, and its javadoc gives the reason:
    an observed rule changes `replaceValue`'s execution kind. ADR-0026 is not amended; codifying the
    rule is raised with the owner separately.
