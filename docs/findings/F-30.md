# F-30 — The Model JSON tab serialises the canonical form in the client

- **Assumption** (ADR-0013, Considered options): "**A client canonical writer**: rejected, because there is
  one writer (ADR-0010)."
- **How it fails**: spec #135 (owner decision, 2026-11-06) adds a read-only Model JSON tab. The tab must show
  the working copy, including unsaved edits, so the UI serialises it itself: `canonicalJson` in
  `ui/src/model/canonical-json.ts` follows the engine's `CanonicalWriter`: code-unit key order, 2-space
  indent, a final LF. It never writes a file. Save still sends the model, and the service writes it.
- **Severity**: minor. It displays only; the one-writer rule for files holds.
- **Evidence**: #139 (merged a097ba3); `ui/src/model/canonical-json.test.ts` compares the output with
  corpus mapping files byte for byte.
- **Change made**: none to ADR-0013. Its wording ("display-only serialiser allowed, one writer for files")
  is an owner question. The fake API keeps its private `sortedKeys`, because the `api` boundary
  (ADR-0013, `ui/eslint.config.js`) forbids it to import `model/`.
