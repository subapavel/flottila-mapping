# F-46 — `copyValue` selects across the whole queue and yields a generating block

Status: accepted (#217, 2026-11-13; re-scoped to class C the same day). The observed rule is clear
and PO 7.5 and CPI agree: `copyValue`'s result is a generating block, which a graph with a source
field can now give (ADR-0006 "generating function" as refined by #217). `fn/copyValue/001`–`004`
are corrected to the observed outputs and green on both back ends; ADR-0006 and ADR-0026 are
amended in the same merge.

- **Assumption** (assumed reading of #79, in `ConstantFunctions.copyValue` and `po:copyValue`; no
  ADR line, ADR-0025 l.59 lists the id only): per context of the input, one context holding the slot
  at the position, counted from 0; a context too short gives an empty context; a SUPPRESS slot is
  copied as SUPPRESS.
- **How it fails**: observed the same on PO 7.50 and CPI (obs-constant, 2026-11-12/13):
  - The position counts from 0 across the whole input queue, context boundaries ignored. Sku in
    context Order is a, b, c | d | e, f: Index 1 selects b, the default Index 0 selects a, Index 3
    selects d (CPI: "selects d across the entire input queue, ignoring context boundaries").
  - That one value goes into every parent occurrence: V b, a, d in all three Items, also in o2's,
    whose context has no such position.
  - A SUPPRESS slot counts as a position and is copied: over `createIf(Tag)`, "", SUPPRESS, "" |
    SUPPRESS, "" | (empty), Index 1 selects SUPPRESS and no Item gets a V.
  - F1's display queue holds one value, with the shape of a `Constant`'s output (PO: `[b]` gray,
    `[b]` dark gray, as C1 in `constant-003`; CPI: "output generator b followed by end marker"),
    not one context per input context. `count` of a constant shows a context and gives V in the
    first Item only (`constant-006`), so the repeat is the generator's, not the target's.
  - The editor proposes Index 0 on both; PO refuses an empty Index, CPI saves it as 0.
  - Not observed: a position beyond the last slot of the queue, an empty queue, and `copyValue`'s
    result at a single-value or context function's input.
- **Severity**: major. Every Item but the matching one differs, and where PO copies SUPPRESS into
  every Item we write an empty V (`fn/copyValue/004`, o2).
- **Evidence**: `corpus/observations/obs-constant/{po75,cpi}/copyValue-00{1,2,3,4}-*.xml` and
  `-check.txt`, `cpi/copyValue-00{1,3,4}-F1-queue.json`, `cpi/copyValue-004-C1-queue.json`,
  `cpi/native-default-copyValue-002.txt`, `po75/constant-003-constant-item-check.txt`,
  `po75/constant-006-constant-count-check.txt`, `meta.json`; #212 comment "Observation run vs
  assumed corpus cases", group G5; red run `.logs/217-oracle-red.log` of `t/217-copyvalue`; green
  run `.logs/217-engine.log` of #217's implementation (`GoldenCorpusTest`, `DifferentialOracleTest`).
- **Change made** (#217, the architect's approved design of 2026-11-13): `copyValue` is a queue
  function the catalogue marks `generating` (ADR-0026, a contract member). Its result is a
  generating block, one context holding the slot at the position of the whole queue, SUPPRESS kept;
  past the last slot, an empty queue's included, one empty context (`ConstantFunctions.copyValue`,
  `po:copyValue`). On a target, lowering makes it a generating `TargetRepeat` whose `value` is the
  block and whose new `valueVar` holds its first slot in the body; `IrVerifier` requires `valueVar`
  exactly for a `QUEUE` value. Both back ends read the block once per run, on first read, and
  write no copy when its first slot is SUPPRESS or missing (`Node.Repeat`; the export's
  `po:queue<n>` and `po:generated` in `core.xsl`), and the trace marks those copies suppressed. At a
  context or queue input the block is that queue; at a single-value input lowering refuses it with
  `unsupported-generating-input`, so the fidelity is `deviation` ("Its result cannot feed a box that
  takes a single value, such as concat. SAP PO accepts that graph."), not `exact`. ADR-0006
  ("Functions by execution kind", "generating function", Consequences) states the observed rule and
  the assumed edges; GLOSSARY gains "Generating block". The case designer's proposals for the
  unobserved edges (a position past the last slot, an empty queue, the block at a context input,
  SUPPRESS under `minOccurs > 0`) go into an observation request after milestone 1. Emulating the
  rule with one context per input context was rejected: it gives the four outputs but contradicts
  the display queues, and differs when the input's context is not the parent's.
