# F-49 — `isNil` is false for an empty element on PO and CPI; only `xsi:nil` is nil

- **Assumption** (ADR-0008, "Assumed readings" and the `xsi:nil` bullet): `xsi:nil` reads as the empty
  string, so `isNil` is true for a nil field and also for an empty element.
- **How it fails**: on PO 7.5 and CPI, `isNil` of an empty `<Sku></Sku>` is false; it is true only for
  `<Sku xsi:nil="true"/>`. Observed `false, true, false, false` for x, nil, empty, one space
  (`obs-boolean` isNil-001). In `obs-structures` nil.xml both write `<V xsi:nil="true"/>` for a nil
  source field; the nil goes through `concat` (the other items give `x!` and `!`), and `exists` is true for
  a nil value.
- **Severity**: minor
- **Evidence**: `corpus/observations/obs-boolean/{po75,cpi}/isNil-001-boolean-isNil.xml`;
  `corpus/observations/obs-structures/{po75,cpi}/nil-str-nil.xml`, `nil.xml`; case `fn/isNil/001`;
  #212 comment "Owner decisions (2026-11-13, second set)", point 1; ticket #221.
- **Change made**: owner decision 2026-11-13. For milestone 1, Flottila keeps ADR-0008's reading (an
  empty element is nil), so `fn/isNil/001` is `decided` and its expected output stays (`false, true, true,
  false`). `isNil` is `{level: "deviation"}` in `boolean.json`: "Treats an empty element as nil. SAP PO
  treats only an element marked xsi:nil as nil." A nil value across the engine (ADR-0008:58, :230) is a
  spec after milestone 1, together with JSON null. ADR-0008 is not edited here.
