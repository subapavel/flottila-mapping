# F-48 — exists is per value and counts SUPPRESS, mapWithDefault keeps a SUPPRESS-only context, useOneAsMany needs one value per context

Status: accepted (owner observation runs of 2026-11-11 and 2026-11-12, `obs-context-functions`
and `obs-useoneasmany`, #212; groups G10, G11 and G13 of the #212 table). ADR-0006 and ADR-0025
amended in the same ticket (#219), under the owner's advance approval of ADR amendments that only
align an ADR with observed PO 7.5 and CPI behaviour (#212, 2026-11-13).

- **Assumption** (ADR-0006 Consequences, "SUPPRESS through the context functions since #51";
  ADR-0025 Consequences, "Assumed (#34): useOneAsMany refuses unless"):
  - `exists` gives one value per context, `true` if it holds a value and `false` if not, and a
    context of SUPPRESS only holds no value (#2 §7.7, #57, assumed);
  - `mapWithDefault` takes a context of SUPPRESS only for empty and fills it (#2 §7.6, #57,
    assumed);
  - `useOneAsMany` takes the values of input 1 in order, whatever its contexts, one per context
    of input 2, and refuses only when the counts differ (#2 §7.10, #34, assumed).
- **How it fails**: observed the same on PO 7.50 and CPI 6.84.77.
  - G10, `exists` keeps the contexts and gives `true` per slot, SUPPRESS and `""` included, and
    one `false` per empty context. ctx-4 on f4.xml: `true,true | false | false | true`;
    `fn/exists/003`: All `true, true, false, false, true`; `fn/exists/004` (createIf output
    `SUPPRESS | SUPPRESS, "" | (empty) | ""`): out `[true] [true,true] [false] [true]`.
  - G11, `mapWithDefault` fills only an empty context: `fn/mapWithDefault/002` keeps
    `[SUPPRESS] [SUPPRESS,""]`, fills the empty context with `D`: All `"", D, ""`. ctx-2 shows
    the same (`[5] | [SUPPRESS] | [D] | [SUPPRESS,3]`).
  - G13, `useOneAsMany` ends the run at the box, before any output, when input 1 has one context
    of two values for input 2's two contexts: "Too few values in the first queue"
    (`fn/useOneAsMany/003`) or "Too many values in the first queue" (`005`, `009`), "It must have
    the same number of contexts as the second queue". A first input with an empty context gives
    "No value found; first queue must have one and only one value in each context" (probe b of
    u4.xml). The probes without the second Order run: a SUPPRESS value is repeated as SUPPRESS
    (no All, `005`), a SUPPRESS occurrence counts (`A, A`, `009`).
- **Severity**: major. `exists` and `mapWithDefault` over `createIf` output, and `useOneAsMany`
  over a value in a wider context, wrote other target elements than PO and CPI, or wrote where
  they stop.
- **Evidence**: `corpus/observations/obs-context-functions/` (`meta.json`, request #33):
  `po75/spec2-exists{.xml,-check.txt}`, `po75/spec2-exists-create-if{.xml,-queue.txt}`,
  `po75/spec2-map-with-default-create-if{.xml,-queue.txt}`, `po75/ctx-2-queue.txt`,
  `po75/ctx-4.xml` and the matching `cpi/` files (`f4-spec2-exists.xml`, `f4-ctx-4.xml`,
  `exists-004-spec2-exists-create-if{.xml,-queue.txt}`,
  `exists-004-spec2-map-with-default-create-if{.xml,-queue.txt}`, the rerun; the initial
  simulation is no reading, `spec2-map-with-default-create-if-check.txt`);
  `corpus/observations/obs-useoneasmany/` (`meta.json`, request #34):
  `po75/u1-spec2-use-one-as-many-root-value.txt`, `cpi/useOneAsMany-003-root-value-error.txt`,
  `{po75,cpi}/useOneAsMany-005-spec2-suppress-use-one-as-many.txt`,
  `{po75,cpi}/useOneAsMany-009-spec3-suppress-use-one-as-many-occurrences.txt`, the probes
  `{po75,cpi}/probe-suppress-value-a-*`, `probe-suppress-occurrence-a-*` and
  `probe-empty-contexts-{a,b,c}-*`. Cases `fn/exists/003`, `004`, `fn/mapWithDefault/002`,
  `fn/useOneAsMany/003`, `005`, `009`.
- **Change made** (#219): the six cases take the observed output or error and become
  `observed`; the three `useOneAsMany` cases become error cases, `po:USEONEASMANY` at U1. ADR-0006
  Consequences amended: `exists` gives `true` per slot and `false` per empty context,
  `mapWithDefault` fills only an empty context, SUPPRESS counting like a value for both.
  ADR-0025 Consequences amended: `useOneAsMany` refuses unless input 1 has as many contexts as
  input 2 and one value, SUPPRESS included, in each, then unless input 3 has as many values as
  input 2; Flottila's messages name the failed count, not PO's words. `ContextFunctions` and
  `po-runtime/context.xsl` follow; the pinned helper module re-pins `po:exists`,
  `po:mapWithDefault` and `po:useOneAsMany` alone (ADR-0026 note, F-39), their changed rule being
  observed. `exists`, `mapWithDefault` and `useOneAsMany` have no assumed case left and become
  `exact`.
