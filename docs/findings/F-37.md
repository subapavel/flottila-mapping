# F-37 — PO's `createIf` throws on a value that is not a boolean

Status: accepted (owner observation #31, spec-2 part, 2026-11-06; drafted as F-23 on the owner's
branch, renumbered at the merge 71ae512 and again to F-37 at #206, because `main` had taken each
number). ADR-0006 amended on the fix ticket's branch, so both reach `main` in one merge; the
error code is `po:CREATEIF`; the case
inputs and the cast-error cases are the red of the fix ticket #133. The values #31 did not try
(`FALSE`, ` true`, SUPPRESS in) are in #134; the boolean family's cast is open (`obs-boolean`).

- **Assumption** (ADR-0006, assumed readings since #51; `ContextFunctions.createIf`): `createIf`
  is true for `1` or `true` in any case, and anything else, `""` and SUPPRESS included, gives
  SUPPRESS.
- **How it fails**: observed the same on PO 7.5 and CPI, mapping spec2-create-if-row
  (`Sku` with context `Orders` -> `createIf` -> `Create/Row`):
  - `true`, `TRUE`, `1` give `""` (created); `false`, `0` give SUPPRESS (probe-bool-a, both
    display queues).
  - `no`, `skip` and `""` (an empty `<Sku/>`) end the run: PO 7.5 "Cannot cast 'no' to boolean"
    (`FunctionException` from `flib7.Bool.toBoolean`), CPI `Cannot cast "no" to boolean.`
    (`BehaviorInvocationException`). No output.
  SUPPRESS as an input was not observed here.
- **Severity**: major. Our runtime writes an output where PO fails the message. The case inputs
  `max-002.xml`, `a2.xml` (spec-2 use) and `suppress-001.xml` use `no` / `skip`, so on PO they fail
  before their question is reached; their expected outputs as written are wrong.
- **Evidence**: `corpus/observations/obs-target-creation/{po75,cpi}/max-002-spec2-create-if-row.txt`,
  `a2-spec2-create-if-row.txt`, `suppress-001-spec2-create-if-item.txt`,
  `probe-bool-{a,b,c,d}-*` and `probes/probe-bool-{a,b,c,d}.xml`; `meta.json`.
- **Change made** (proposed, not yet made): `createIf` reads its input with PO's boolean cast:
  `true`/`1` true, `false`/`0` false, case-insensitive; any other value, `""` included, is a data
  error at the box (a new or existing `po:` error code, chosen in the ADR). Amend ADR-0006's
  assumed truth rule and mark it observed. Check whether the other boolean functions share
  `Bool.toBoolean` (an observation, not an assumption). Rewrite the three case inputs with `false`
  in place of `no` / `skip`: probe-bool-b answers `target/max/002` (= a1 of create-a), probe-bool-d
  answers `target/suppress/001` (V 10, then 30), and a2 of create-a answers `target/minOccurs/002`.
  Keep one case for the error itself.
