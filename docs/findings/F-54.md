# F-54 — `/gate` ran the ratchet check before any build, so every row was NOT_RUN

Status: accepted (#229, 2026-11-14).

- **Assumption** (`.claude/skills/gate/SKILL.md` step 2, F-41; `docs/GATE.md` check 8): the gate runs
  `java scripts/ratchet.java check` "before the spec gate's step 3 `clean`", and the result shows that
  the ratchet is green on the gate commit.
- **How it fails**: the gate run of #226 ran the check before any build. The check reads the oracle
  lists and the JaCoCo and PIT reports, which a build writes, so none existed. Every measured row is
  `NOT_RUN` and the last line, `RATCHET CHECK OK`, says nothing about coverage or mutation. Check 8
  rested on `regen --all` instead. The rule "before step 3" did not say that the reports must exist
  first.
- **Severity**: minor
- **Evidence**: `.logs/gate-8-ratchet.log` of the #226 gate run (worktree `gate-m1b`): two oracle rows,
  eleven coverage rows and seven mutation rows, all `NOT_RUN`, then `RATCHET CHECK OK`.
  `scripts/gate-spec.sh` runs 1, 1b, 2, 5, 4, 3, and its step 4 reads the reports of steps 1, 1b and 2.
- **Change made** (#229): `.claude/skills/gate/SKILL.md` step 2 runs the check after the spec gate's
  step 1b (the reports exist) and before its step 3 `clean`, which deletes them. The script test
  `scripts/test/handover-test.sh` checks the order.
