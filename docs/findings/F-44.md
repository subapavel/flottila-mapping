# F-44 — The boolean family casts as PO's Bool.toBoolean does; ifWithoutElse gives SUPPRESS for false

Status: accepted (observation run obs-boolean, PO 7.50 and CPI, 2026-11-12/13; #212 groups G1 and G3).
Fix ticket #215; ADR-0006 amended on its branch under the owner's advance approval (#212,
2026-11-13). `isNil` (G2) is not part of it.

- **Assumption** (ADR-0006 Consequences, open question on the boolean family; ADR-0025 and spec
  #70, #77, #78; `BooleanFamily`, `BooleanFunctions.ifWithoutElse`, `boolean.xsl`): only the exact
  text `true` is true and anything else is false, no error. `equals` / `notEquals` compare text.
  `ifWithoutElse` pairs its inputs as a Lift does (an empty or missing context gives an empty
  one), and a false condition leaves no slot unless `keepSuppressValues` (default false) asks for
  SUPPRESS.
- **How it fails** (PO 7.50 and CPI agree on every case):
  - G1. `and`, `or`, `not`, `equals`, `notEquals` and `if` end the run with the cast error on the
    first value that is no boolean: `Cannot cast '' to boolean` (and line 4, or line 5, not line
    5, if line 4), `Cannot cast 'keep' to boolean` (equals, notEquals line 1). PO names
    `flib7.Bool` methods `and`, `or`, `not`, `equalsBoolean`, `notEquals`; CPI raises
    `BehaviorInvocationException: Cannot cast "" to boolean.` No output. `TRUE` and `1` in earlier
    lines cast without error.
  - G3. `ifWithoutElse`: a false condition gives SUPPRESS whatever "Keep SUPPRESS Values" says
    (001 with the parameter off gives a, c, d like 002 with it on; display queues of X1 in 001 and
    X1/X2 in 007 show SUPPRESS); `TRUE` is true (003: o2's Item gets d); a SUPPRESS condition gives
    SUPPRESS (007: V true, true); in 005 both false lines give SUPPRESS (V 1, true). On the context
    shape: an empty condition context against the value z gives one slot that creates nothing (PO
    shows `<null>`, CPI `[ ]`), and a false condition against an empty value context one SUPPRESS
    (008 display queue: X1 is [·] [SUPPRESS] [x, SUPPRESS], so the one Item is at slot 3, V c); a
    value context beyond the condition's last gives an empty All under collapseContexts (009: a,
    empty, confirmed), while a condition context beyond the value's last gives no context at all
    (010: only All x). The parameter's effect was never seen in any case.
- **Observed rule.** Each boolean value is cast as PO's `Bool.toBoolean`: `1` and `true` in any
  case are true, `0` and `false` in any case false (as `createIf`, F-37); any other value, `""`
  included, is a data error at the box. `equals` / `notEquals` compare the cast values.
  `ifWithoutElse` has as many result contexts as its `then` input; context i is empty where the
  condition has no context i; otherwise the longer context sets the slot count, the shorter reuses
  its last value, and an empty one gives SUPPRESS at every slot of the other; SUPPRESS in either
  input, or a false condition, gives SUPPRESS; a true one gives the value.
- **Readings this rule adds, not observed:** the error code (`err:FORG0001`, below); `and` / `or`
  cast both values, the second even where the first decides; `ifWithoutElse` casts only a
  condition paired with a value and raises a non-boolean one, as the family does; PO's `<null>` of
  008 is SUPPRESS here (the engine has no null; both create nothing and keep their slot); a value
  context beyond the condition's last is an empty context rather than one such slot per value:
  both give 009's empty All under today's collapseContexts, and only the empty context still does
  if collapseContexts keeps SUPPRESS, as obs-context-functions ctx-6b shows.
- **Severity**: major. The runtime and the export wrote output where PO and CPI fail the message,
  and placed or dropped target occurrences differently from PO.
- **Evidence**: `corpus/observations/obs-boolean/{po75,cpi}/` — `and-001-boolean-and-error.txt`,
  `or-001-…`, `not-001-…`, `equals-001-…`, `notEquals-001-…`, `po75/if-001-boolean-if-error.txt`,
  `cpi/if-001-boolean-if-native-error.txt`; `ifWithoutElse-00{1,3,5,7,8}-*.xml` and `-check.txt`,
  `ifWithoutElse-010-*`, `cpi/ifWithoutElse-001-queue.json`, `cpi/ifWithoutElse-007-X{1,2}-queue.json`,
  `cpi/ifWithoutElse-008-X1-queue.json`; `meta.json`. Cases `fn/and/001`, `fn/or/001`,
  `fn/not/001`, `fn/equals/001`, `fn/notEquals/001`, `fn/if/001`, `fn/ifWithoutElse/001`, `003`,
  `005`, `007`, `008`, `010` (red: `.logs/215-oracle-red.log` on `t/215-boolean-cast`); kept green:
  `fn/ifWithoutElse/002`, `004`, `009`.
- **Change made** (#215): the twelve cases take the observed output or error and provenance
  `observed`. `BooleanFunctions.truth` is the one cast, shared with `createIf` (whose behaviour and
  `po:CREATEIF` are unchanged). The family's single-value functions raise `err:FORG0001` at the box,
  the code every standard function's malformed value has (ADR-0025 "Data errors name their box",
  ADR-0006 Typing: a failed cast raises FORG0001); `ifWithoutElse`, a context function of the same
  family, raises the same code, as the statistic family's queue functions do. The export's
  `boolean.xsl` does the same and its functions but `po:isNil` take `box` last; no pinned helper
  block changes. `and`, `or`, `not`, `equals`, `notEquals` and `if` become `exact`;
  `ifWithoutElse` becomes `exact` with #214, which observed 002, 004 and 009 (006 is decided).
ADR-0006 amended.
