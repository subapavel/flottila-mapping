# F-24 — engine tests resolve over a test directory, not only in memory

- **Assumption** (ADR-0014 "Decided for spec 4", 2026-11-05): "Engine tests use an in-memory one",
  meaning an in-memory reference resolver.
- **How it fails**:
  - #90's approved design narrowed this to "a test-scope in-memory or map resolver over
    `corpus/`". The ADR text was not amended with it.
  - The engine and oracle tests read the corpus from disk, as `GoldenCorpusTest` always has. So
    #90 gives `engine/structure-import`, `engine/api` and `engine/oracle` each a test-scope
    `DirectoryResolver` over a test directory.
  - The #90 Standards review found the contradiction with the ADR.
- **Severity**: minor (wording). The rule's intent holds: no production code in the engine opens a
  file (ADR-0016 rule F), and the resolvers are test classes outside the ArchUnit import.
- **Evidence**: #90 Standards review (FAIL, blocking item 1); the three
  `src/test/.../DirectoryResolver.java` files on `t/90-resolver-port`.
- **Change made**: ADR-0014 now reads "Engine tests use a test-scope resolver, in memory or over a
  test directory such as `corpus/` … It is never a production class." The modules share no
  test-jar, so each keeps its own copy.
