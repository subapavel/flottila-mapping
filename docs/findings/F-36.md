# F-36 — Runs on the same machine label differ by far more than the 20 % ratchet tolerance

- **Assumption** (`ratchet/README.md`, ADR-0021): one label, `claude-cloud-4vcpu`, names one comparable
  machine; a bench row moves only beyond a 20 % tolerance (`ms/op`, `us/op`, `ms`, `MB/s`).
- **How it fails**: three runs of the same engine code on that label gave scores that differ by 36 to 71 %
  of the median (spread = (max - min) / median): `compile/orders` 43 %, `contexts/small/latency` 55 %,
  `orders/small/latency` 36 %, `wide/small/latency` 43 %, `contexts/large/throughput` 55 %,
  `orders/large/throughput` 71 %, `wide/large/throughput` 62 %. Allocation (0 to 1 %) and the tree scroll
  (1 %) are stable. Run 1 (host not recorded) was about 1.5 to 2 times faster than runs 2 and remote, which
  reported the same CPU line (Xeon 2.10 GHz, 4 CPUs, about 16.47 GB). The CPU model name does not tell the
  hosts apart; noisy neighbours or a different CPU generation under the same name are both possible. A
  baseline taken on a fast host makes a later run on a slow host look like a regression, and the reverse
  hides one.
- **Severity**: major (the bench ratchet can fail or pass by the host alone)
- **Evidence**: `bench/RESULTS.md` section "Spec 6 first measurement"; #189 and its measurement comment;
  runs on 5a2515f (two) and 001da99 (one, the same engine code); #193 (median of three) and #194.
- **Change made**: none. #193 judges targets on the median of three runs, which narrows the target judgement
  but not the 20 % tolerance of the stored baselines.

Open owner question: should the label be split by CPU model (so a fast and a slow host never share a
baseline), or should the baseline be taken only from the spec gate's host (and runs elsewhere stay
informative)? A third option is one label with a wider tolerance for the time units; the data above suggests
about 75 % would be needed. Note that the CPU model name was identical on both hosts that recorded it, so a
split by model name alone would not separate them; a finer key (for example a calibration score) would be
needed.
