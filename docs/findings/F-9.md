# F-9 — the "a corpus case per code" check cannot live in `engine/api`

- **Assumption** (ADR-0018 §Drift tests): a test in `engine/api` collects every module's codes,
  checks kebab-case and uniqueness, checks that at least one corpus case raises each code, and
  checks that no case expects a code that does not exist.
- **How it fails**:
  - Only `engine/oracle` reads the corpus, and `engine/api` must not depend on it (ADR-0016).
  - About 20 design-time codes from #24 and #25 have module tests and no corpus case. Their
    behaviour is tested at the module seams, and a corpus case id is permanent.
  - A code such as `unsupported-box-kind` disappears once function boxes compile.
- **Severity**: minor
- **Evidence**: #26 design draft (2026-10-31).
- **Change made**:
  - `engine/api` keeps `DiagnosticCatalogueTest`: every code is kebab-case and unique across
    modules, and every code-shaped string constant in the engine's classes is a catalogue code.
  - The corpus half (no case expects an unknown code) moves to `engine/oracle`.
  - "At least one case per code" applies to runtime error codes (`po:*`, `err:*`, `flottila:*`)
    from spec 2 on, not to design-time codes.
  - ADR-0018 is amended.
