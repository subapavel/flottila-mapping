# F-7 — XmlSchema 2.3.3 gives no line or column, so the XSD reader adds a SAX pass

- **Assumption** (ADR-0008 §Readers): XSD uses Apache XmlSchema 2.3.3, and load errors carry
  file, line and column.
- **How it fails**: XmlSchema 2.3.3 never sets a line or column on its objects; no code in the
  jar calls `setLineNumber`. It is also an automatic module, which ADR-0017 allowed to lift the
  `requires-automatic` lint only for json-sKema.
- **Severity**: minor
- **Evidence**: #25, `t/25-flat-xsd` @ 2cd714a. `StructureReaderTest` refusal cases locate their
  errors by file, line and column.
- **Change made**:
  - `structure-import` runs a JDK SAX pass with DOCTYPE refused in front of XmlSchema, and the
    SAX pass supplies the positions.
  - ADR-0008 now says so, and spec 4 inherits the pass.
  - ADR-0017 allows `-Xlint:-requires-automatic` in the modules that read json-sKema or
    XmlSchema.
  - A text-content refusal points at the end of the text, which can be one line late. That is
    accepted.
