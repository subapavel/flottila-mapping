# F-47 — SUPPRESS sorts last, collapseContexts keeps SUPPRESS and gives nothing for an empty queue

Status: accepted (owner observation run of 2026-11-11 and 2026-11-12, `obs-context-functions`,
#212; groups G6, G8 and G9 of the #212 table). ADR-0006 amended in the same ticket (#218), under
the owner's advance approval of ADR amendments that only align an ADR with observed PO 7.5 and CPI
behaviour (#212, 2026-11-13).

- **Assumption** (ADR-0006 Consequences, "SUPPRESS through the context functions since #51"):
  - `sort` and `sortByKey` order a SUPPRESS value or key as the smallest in every comparison, first
    ascending and last descending (assumed);
  - `collapseContexts` takes a SUPPRESS first slot as `""` (#2 §3 [SAP✓ STD] "Empty contexts
    (= ResultList.SUPPRESS) are replaced by empty strings", documented);
  - `collapseContexts` replaces every empty context with `""`, so a source queue whose context
    element never occurs, one empty context (F-17), gives one `""` (assumed, `fn/collapseContexts/003`).
- **How it fails**: observed the same on PO 7.50 and CPI 6.84.77; the display queues are the
  rule's evidence, the outputs agree on both systems.
  - G6, `sort` (case-sensitive) and `sortByKey` (case-sensitive, ascending): SUPPRESS is the
    greatest key. `fn/sort/012`: ascending gives `"", "", SUPPRESS, SUPPRESS`; `fn/sort/013`:
    descending gives `SUPPRESS, SUPPRESS, "", ""`; `fn/sortByKey/006`: the SUPPRESS keys sort after
    the empty keys, ties in input order, values `s1, s3, s2, s4`.
  - G8, `fn/splitByValue/019` to `021`: `splitByValue` keeps each SUPPRESS as a slot, as ADR-0006
    assumed, in Each value, Value change and Empty value. What differs is the `collapseContexts`
    after it: it keeps a SUPPRESS first slot as SUPPRESS (PO queue of 019: in `"" | S | "" | S | S`,
    out `"", S, "", S, S`), so the root writes two, two and one empty `All`. `ctx-6b` shows the
    same on both systems: `5 | SUPPRESS | 7` collapses to `5, SUPPRESS, 7` and writes `All` 5, 7.
  - G9, `fn/collapseContexts/003` (`<Orders/>`): no `All`; both queues hold only the start and end
    markers. An empty context among others still gives `""` (`fn/collapseContexts/001`, `002`,
    `fn/splitByValue/021`). PO's queue holds one empty context as nothing at all, no value and no
    context change, the same as no context; for that queue `collapseContexts` writes no value.
- **Severity**: major. A sort or a collapse over `createIf` or `ifWithoutElse` output, a common PO
  pattern, wrote other target elements than PO and CPI do.
- **Evidence**: `corpus/observations/obs-context-functions/` (`meta.json`, request #33):
  `po75/spec2-suppress-sort-format-012{.xml,-queue.txt}`,
  `po75/spec2-suppress-sort-descending-format-013{.xml,-queue.txt}`,
  `po75/sortByKey-006-spec2-suppress-sort-by-key{.xml,-check.txt}`,
  `po75/splitByValue-0{19,20,21}-spec2-suppress-split-*{.xml,-check.txt}`,
  `po75/spec2-collapse-contexts-003{.xml,-queue.txt}`, `po75/ctx-6b{.xml,-queue.txt}` and the
  matching `cpi/` files (`sort-012-*`, `sort-013-*`, `sortByKey-006-*`, `splitByValue-019-*`,
  `splitByValue-020-*`, `splitByValue-019-spec2-suppress-split-empty-collapse.xml` for 021,
  `collapseContexts-003-*`, `f6-ctx-6b*`). Cases `fn/sort/012`, `fn/sort/013`, `fn/sortByKey/006`,
  `fn/splitByValue/019`, `020`, `021`, `fn/collapseContexts/003`; `fn/collapseContexts/004` (its
  documented reading contradicted by ctx-6b; its own input was not run).
- **Change made** (#218): the eight cases take the observed rule, and seven become `observed` on
  their own runs. `fn/collapseContexts/004` becomes `decided` (architect, #218, as
  `fn/createIf/002` was by F-37's rule in #221): its expected output is derived from the rule
  observed in ctx-6b, its own input was never run, and its observation request follows milestone
  1; `observed` would claim a run, and `assumed` is barred by GATE check 4. ADR-0006
  Consequences amended: `sort` and `sortByKey` take SUPPRESS as the greatest value or key
  (observed for a case-sensitive `sort` both ways and an ascending `sortByKey`; the other
  comparisons and a descending `sortByKey` follow the same rule, assumed); `collapseContexts`
  keeps a SUPPRESS first slot and gives no value for a queue with no slot and at most one context.
  `target/structureField/004`, the structure-field twin of `fn/collapseContexts/003` (`decided`),
  takes the same collapse: no `Item`. `collapseContexts` and `splitByValue` have no assumed case
  left and become `exact`; `sort` and `sortByKey` take the deviation of F-43 (ADR-0026), its text
  corrected: PO 7.50, CPI and Flottila agree on the case-sensitive order `z, 😀, ﬀ, Ａ` (UTF-16
  code units, `fn/sort/002`: po75/spec2-sort-002.xml, cpi/sort-002-spec2-sort.xml); they differ
  only case-insensitively, where Flottila and CPI compare code points (`z, ﬀ, Ａ, 😀`) and PO
  gives `z, 😀, ﬀ, Ａ` (`fn/sort/004`, `fn/sortByKey/002`). F-43's "Compares text by Unicode
  character (code point)" named every comparison, so both texts now say case-insensitively.
  `ContextFunctions` and `po-runtime/context.xsl` follow; the pinned helper module re-pins
  `po:collapseContexts`, `po:sort-contexts` and `po:sortByKey-context` alone (ADR-0026 note, F-39),
  their changed rule being observed, not a new raise as F-39 names.
