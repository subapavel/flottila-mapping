# F-2: an unfinished target field mapping has no result yet

- **Assumption** (ADR-0010, §Document): "`targetFieldMappings` … Each entry is `{id, result,
  boxes}`. `result` is the id of the box whose output feeds the field."
- **How it fails**: in the editor prototype (#10), an author puts boxes on the canvas before
  wiring any of them to the target field. With `result` required, that state cannot be saved.
  The prototype had to use `null`.
- **Severity**: minor
- **Evidence**: prototype #10, branch `prototype/mapping-editor`, at 3a5ed86. The owner decided
  this on 2026-10-30.
- **Change made**:
  - ADR-0010: `result` is a box id or `null`, just as an unconnected input is `null`. A field
    with no boxes still has no entry.
  - ADR-0011, stage 3: compiling a `null` result raises the design-time error "unconnected
    target field", carrying the target field mapping's `AuthoringId`. The editor marks the field
    as an error.
