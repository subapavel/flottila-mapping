# F-29 — ADR-0013 has no styling rule; spec #135 sets one that needs an owner

- **Assumption** (ADR-0013, "Modules of `ui/src`" and "Tests and browser feedback"): the ADR fixes the editor's
  modules, state and tests, and is the UI's architecture record. It says nothing on how the UI is styled, and
  spec 5 (#104) styled nothing: static inline `style={{}}` objects and PatternFly defaults.
- **How it fails**: spec #135 (the editor look) needs a rule for many tickets at once, so the spec set it: one
  plain `.css` file per UI module, imported by that module's component; class names with the `fm-` prefix;
  colours and spacing from PatternFly tokens (`--pf-t--global--*`); static inline styles move to the module's
  CSS, and inline styles stay only for values computed at run time (splitter grows, virtualiser offsets, canvas
  positions). The rule lives in a spec, not in an ADR, so the next UI spec does not inherit it.
- **Detail found in #136**: the file is named after its module (`ui/src/editor/editor.css`,
  `ui/src/app/app.css`), not after the component: a `MappingEditor.css` beside `MappingEditor.tsx` shares its
  path once the extension is ignored, which `ui/src/file-names.test.ts` refuses (#131, case-insensitive file
  systems).
- **Severity**: minor (no behaviour; a convention without an owner drifts between tickets)
- **Evidence**: spec #135 "Implementation Decisions" (styling convention); ticket #136; `ui/src/editor/editor.css`,
  `ui/src/app/app.css`.
- **Change made**: the convention is applied to the header bar, the page tabs and the layout (#136). Owner
  question: amend ADR-0013 with the styling rule, or record it in a new ADR.
