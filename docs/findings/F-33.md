# F-33 — UDFs cannot be in milestone 1: they depend on Flottila's data model

- **Assumption** (GATE.md check 6, spec 7; grilling #19; ADR-0020): milestone 1 ships Java UDFs. They would be compiled in-process, isolated, and backed by a container API and `MappingRun`.
- **How it fails**: the owner decided on 2026-11-10 that the UDF API must expose Flottila's message model, which does not exist yet. That model covers headers, properties, attachments and channels. Building UDFs now would fix an API before the data it serves.
- **Severity**: major. It changes a gate check.
- **Evidence**: the owner's decision in the spec #152 session (2026-11-10); the backlog comments on #165, #167, #168, #169 and #171.
- **Change made**:
  - ADR-0030 supersedes ADR-0020's place in milestone 1.
  - GATE.md: check 6 removed; the UDF lines left check 3; `udf-api` and `udf` left check 8; spec 7 removed; `HANDOVER.md` moved to spec 6; the deferred features listed after milestone 1.
