# F-25 — json-sKema hides the walk's refusals behind earlier load errors

- **Assumption** (ADR-0008, spec-4 grilling, 2026-11-05): "One load reports every load-time
  error of the bundle: files in bundle order, each file in document order."
- **How it fails**:
  - json-sKema 0.32.0's loader either returns the whole schema or throws. It never returns a
    partial schema.
  - Our walk over the loaded schema finds four refusals: a root that is not an object, an array of
    arrays, a property with two shapes, and a type-list member that is not a string. It can run
    only when the file loaded.
  - Before json-sKema runs, the reader reports:
    - a refused `$schema`, which stops that file;
    - `$dynamicRef` and `$ref`s outside the bundle, which are dropped before the load.
  - json-sKema's own problems are all reported, whether it throws one or an aggregate.
  - A JSON Schema file with any of those errors therefore hides its walk refusals until they are
    fixed.
- **Severity**: minor. Every load still reports every error the reader can see. An author who
  fixes the first set may meet a second set on the next load. XSD and WSDL are unaffected.
- **Evidence**: the #97 hand-back on `t/97-json-schema-reader` a7853c1, with the `everyError` rows in
  `JsonSchemaReaderTest` (red 7344970, green a7853c1).
- **Change made**: ADR-0008 "JSON Schema (#97)" records the exception. A reader that can return a
  partial schema would lift it.
