# F-17 — A source queue has at least one context: absent everywhere is one empty context

Status: accepted (owner observation #31, 2026-11-02; numbered F-14 on the owner's branch, renumbered
F-17 at the merge f6b5d2d because F-14 was taken). ADR-0004 and GLOSSARY "Empty context" amended;
the fix ticket is #64.

- **Assumption** (ADR-0004, Consequences, assumed reading 2; Considered options, "a minimum of one
  context: rejected ... cannot express an absent parent"; GLOSSARY "Empty context"): an absent
  parent gives zero contexts (`{0}`), not one empty context (`{0,0}`).
- **How it fails**: observed on PO 7.5 and CPI, mapping create-d of `obs-target-creation`
  (`Orders/Order/Memo/Text`, default context `Memo`, into `mapWithDefault{default=D}`, onto
  `Out/Item/V` with `Orders/Order -> Out/Item`):
  - d1 (Memo under orders 1 and 3, absent under order 2): queue `[a] [c]`. The absent `Memo` adds
    no context, as assumed. Item 3 gets no `V`.
  - d2 (empty `<Memo/>` under order 2): queue `[a] [] [c]`, output `D` in Item 2, as assumed.
  - d3 (no `Memo` under any order): queue `[]`, **one empty context**. `mapWithDefault` gives
    `[D]` and Item 1 gets `V` = `D`; Item 2 gets none. Assumed was no `V` at all.
  Both systems agree. The reading that fits all three: a context is closed by a context change,
  so the number of contexts is the number of context-element occurrences, but never less than one.
  A queue whose context element never occurs is one empty context. Only d3 tests that case;
  the other inputs of #31 always have their context element.
- **Severity**: major. `mapWithDefault` (and every function that reacts to an empty context) on an
  optional segment that is absent from the whole message is a common PO pattern; with the assumed
  reading our runtime drops the default value that PO writes.
- **Evidence**: `corpus/observations/obs-target-creation/{po75,cpi}/d1-create-d*`, `d2-create-d*`,
  `d3-create-d*` and `meta.json` (PO 7.50 SP33, CPI 6.84.77), commits `8c29ac7`, `fa6c434` on
  `claude/sharp-hypatia-hkhf88`.
- **Change made** (proposed, not yet made): keep the queue block (ADR-0004); it already holds
  both `{0}` and `{0,0}`. Change the projection rule: a `SourceQueue` whose context element has no
  occurrence in the input is `{0,0}`, one empty context, not `{0}`. Amend ADR-0004 in the same
  merge: replace assumed reading 2 by the observed rule, mark it observed, and reword the rejected
  option "a minimum of one context" (PO has that minimum for source queues; `{0}` stays legal for
  function results until an observation says otherwise). Amend GLOSSARY "Empty context" the same
  way. The fix ticket starts red from the d3 case of the `oracle:corpus` ticket for #31.
