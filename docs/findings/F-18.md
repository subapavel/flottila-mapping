# F-18 — the XSLT export's first-read rule rests on Saxon laziness

- **Assumption** (spec #48 story 29, ADR-0006 "TargetSlots"): the export runs on any XSLT 3.0
  processor and evaluates a `TargetSlots` queue at most once, on first read.
- **How it fails**: the export hoists a queue under an occurrence into a `po:queue<n>` variable in
  the root template. That it is evaluated only on first read is Saxon-HE 12.5's lazy evaluation of
  variables, observed but not required by XSLT 3.0. An eager processor would evaluate a queue whose
  field is never created, which can raise an error PO would not raise.
- **Severity**: minor (Saxon-HE is the only processor the gate runs; behaviour pinned by
  `target/firstRead/001`–`002`)
- **Evidence**: #52 spec re-review; ADR-0006; spec-2 review (reviewer-spec, carried item 11)
- **Change made**: none in spec 2. ADR-0006 records the reliance. Deferred to the export spec,
  which must either guard each hoisted queue by its parent's existence or name Saxon as the
  supported processor.
