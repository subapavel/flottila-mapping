# F-32 — The browser state keeps the page tab and the selected target field per mapping

- **Assumption** (ADR-0013, Browser state): "per mapping: the expanded tree branches and the status
  filter". The list names nothing else per mapping.
- **How it fails**: practice keeps two more things per mapping. Spec #135 added the page tabs (Editor,
  Test, Diagnostics, Model JSON) and keeps the active one under `mapping:<id>:page-tab`. Spec #145
  (#147) opens a mapping on a target field and keeps the selected one under `mapping:<id>:target-field`.
  On the next open, that field is selected again while the target structure still has it. Both are view
  state, and neither is in the model, so they belong to the browser state, but the ADR's list does not
  name them.
- **Severity**: minor. Both follow the ADR's rules: they sit under the same prefix, every read falls back to
  the defaults, and nothing reaches the model.
- **Evidence**: b3077f2 (spec #135) and #147 (merged 727fa5c). See `MappingEditor.browser.test.tsx`: "the
  active page tab is kept per mapping in the browser state; …" and "the selected target field is kept in
  the browser state and selected on the next open; …". The key of the selected target field is
  `targetFieldKey` in `ui/src/editor/browser-state/browser-state.ts`, tested in `browser-state.test.ts`.
- **Change made**: none to ADR-0013. Adding the page tab and the selected target field to its "per
  mapping" line is an owner question. It can go in the same ADR-0013 amendment that F-29 to F-31 ask for.
