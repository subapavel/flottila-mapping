# F-31 — A helper that starts to raise re-pins the #69 byte fixture again

Status: accepted (#133, 2026-11-06). ADR-0026 Consequences amended in the same merge.

- **Assumption** (ADR-0026, Consequences): "#71 re-pins the two byte fixtures of #69 once ...
  The family tickets that follow keep the new pins green."
- **How it fails**: F-29 makes `po:createIf` raise a data error (`po:CREATEIF`). ADR-0026 requires
  a raising helper to take `box` as its last param, so the helper's declaration changes and
  `engine/xslt-export/src/test/resources/pinned-71/po-runtime.xsl` cannot stay byte-equal. "Once"
  assumed that no existing helper would start to raise; an observation can overturn that.
- **Severity**: minor. The fixture's assertions are unchanged; only the `po:createIf` block moved.
- **Evidence**: `t/133-createif-cast` (de2ead2 and its parents), `XsltExporterTest` javadoc of
  `MAIN_HELPER_MODULE`; hand-back of #133.
- **Change made**: ADR-0026 amended: a ticket whose observed rule makes an existing helper raise
  re-pins that helper's block alone, names the finding or ADR amendment that requires it in the
  fixture's javadoc, and leaves every other byte and every assertion as they are.
