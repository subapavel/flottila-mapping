# F-27 — Compile results and test runs live in the working-copy store, not TanStack Query

- **Assumption** (ADR-0013 §State): "Server data goes through TanStack Query 5: … compile results and test
  runs"; the module list names the editor folders.
- **How it fails**: a compile answer belongs to one version of the working copy. The compile scheduler
  debounces edits, drops an answer for a stale version, and a test run marks its trace stale when the working
  copy changes. Spec #104 decided to hold both in the Zustand working-copy store next to the undo history
  (#105, #113), where that coupling is one module. TanStack Query would key them by a request, not by a
  working-copy version. `editor/diagnostics/` (#105) is also missing from ADR-0013's module list.
- **Severity**: minor (the code is the spec's decision; the ADR wording lags)
- **Evidence**: `ui/src/editor/store/working-copy.ts` (compile scheduler, `recordRun`, `selectTraceStale`),
  `ui/src/editor/MappingEditor.tsx`; spec 5 review round 1 (#104 comment 6683228224).
- **Change made**: none to the code. The ADR-0013 wording is owner question #129 (the owner declined an ADR
  amendment earlier in this run). The spec 5 PR names it as a deviation.
