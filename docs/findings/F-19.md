# F-19 — a data error in the export does not name its box

- **Assumption** (GATE check 3, ADR-0015): a runtime error returns its QName and the authoring id of
  the element that raised it.
- **How it fails**: the runtime attaches the box's authoring id to a context function's data error
  (ADR-0025), but the export's `po:` functions raise `po:<NAME>` with no box: ADR-0025 gives them
  only the `FunCall` args (spec-2 review, Standards a2). Spec 3 adds many functions that raise
  data errors (arithmetic, date, formatNum), so the gap would grow per function.
- **Severity**: major for spec 3; no export has been handed out yet.
- **Evidence**: spec-2 review (reviewer-standards, a2); po-runtime.xsl `po:useOneAsMany`,
  `po:at-least` before the review fix.
- **Change made**: ADR-0025 amended (owner, spec-3 grilling Q12). A `po:` function that can raise
  a data error takes the box id as its last argument and names it in the message. The spec-3
  catalogue ticket applies this to the existing context functions; `po:at-least` already does
  (spec-2 review fix).
