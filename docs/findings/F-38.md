# F-38 — A mandatory target field reads a context its queue lacks: PO reuses the last value

Status: open, deferred past milestone 1 (owner, 2026-11-13, #220). Owner observation #31, spec-2
part, 2026-11-06; drafted as F-24 on the owner's branch, renumbered at the merge 71ae512 and again
to F-38 at #206, because `main` had taken each number. The follow-up observation #134
(`obs-target-creation-2`) narrows the question but does not separate padding from the error, so
the `min` rule is not changed: ADR-0006 keeps marking it contradicted, and `target/minOccurs/004`
keeps its expectation.

- **Assumption** (ADR-0006, target slots: "A context the queue lacks counts as empty (assumed for
  the `min` check)"; case `target/minOccurs/004`): when the parent has more occurrences than the
  child queue has contexts, the extra parent occurrence reads an empty context, and a child with
  `minOccurs > 0` raises `po:MINOCCURS`.
- **How it fails**: observed the same on PO 7.5 and CPI, mapping
  spec2-nested-grp-row-remove-contexts, input `minOccurs-004.xml`. `Grp` (0..n) per `Id` with
  context `Orders`: o1, o2. `Row` (1..2) = `removeContexts(Sku)`: one context `[a, b]` (both display
  queues). Grp 1 gets Rows a and b. Grp 2 gets **one Row with value b**, the last value of the
  queue, and the run succeeds. Not the whole last context (that would be a and b again).
  Compare #31 d1 (create-d): an optional field (`V`, 0..n) under a parent occurrence whose context
  the queue lacks gets no occurrence.
- **Follow-up** (#134, `obs-target-creation-2`, 2026-11-11). Same boxes and input
  `minOccurs-004.xml` unless named:
  - mc-min2 (`Row` 2..2), PO and CPI: Grp 1 Rows a, b; Grp 2 **two Rows b, b**. The last value is
    padded up to `min`.
  - mc-opt (`Row` 0..2), PO only (CPI ENVIRONMENT_BLOCKED, a previous-session lock): Grp 2 is
    empty. With #31 (`Row` 1..2: one b), the padding follows `min`: 0 gives none, 1 one b, 2 b, b.
  - mc-memo (`Row` 1..2, direct source `Orders/Order/Memo/Text`, no function; input
    `mc-memo-1.xml`, queue `[a] [b]`, three Grp), PO and CPI: the run ends with
    `IllegalInstanceException` at `/Doc/Grp[3]/Row`, "Values missing in queue context" (PO; CPI
    "Queue has not enough values in context"). Grp 3 reads a context the queue lacks, as Grp 2 does
    in case 004, but the last value b is **not** padded (meta.json:27). This is the current rule:
    a missing context counts as empty and raises `po:MINOCCURS`.
  - mc-memo-opt (`Row` 0..2), PO and CPI: `mc-memo-1.xml` leaves Grp 3 empty; `mc-memo-2.xml`
    (queue `[a] []`) leaves Grp 2 and Grp 3 empty, a is not reused.
- **Open question**: the observations do not separate padding (case 004, mc-min2) from the error
  (mc-memo). Each of these readings fits every run:
  - (a) the queue's last context already reached `max` (`[a, b]`, max 2) against not (`[b]`, max 2);
  - (b) a function's result queue (`removeContexts`) against a source queue;
  - (c) a queue of one context against one of several;
  - (d) PO's cursor: a slot that stops at `max` leaves the end marker unread, and a later read below
    `min` repeats the marker's value (R1's display queue shows the dark-gray end marker as `[b]`).
  A rule "a missing context pads the last value up to `min`" would break mc-memo, where PO and CPI
  raise the error.
- **Severity**: major. PO writes an output where we raise `po:MINOCCURS`.
- **Evidence**: #31: `corpus/observations/obs-target-creation/{po75,cpi}/minOccurs-004-spec2-nested-grp-row-remove-contexts.xml`
  and `-queue.txt`; d1 under `{po75,cpi}/d1-create-d*`; `meta.json`. #134:
  `corpus/observations/obs-target-creation-2/{po75,cpi}/minOccurs-004-mc-min2.xml`,
  `po75/minOccurs-004-mc-opt.xml`, `po75/minOccurs-004-mc-opt-queue.txt`,
  `{po75,cpi}/mc-memo-1-mc-memo.txt`, `{po75,cpi}/mc-memo-{1,2}-mc-memo-opt.xml`, `meta.json`
  (notes, :27 for mc-memo; runs); `request.md` part 1.
- **Next step** (after milestone 1): a follow-up observation that separates (a) to (d), for example
  mc-memo's mapping with two Texts under o2 (a source queue whose last context reaches `max`), and
  `removeContexts` over a queue with one value in its only context under `Row` 1..2 with three
  `Grp` (one context, below `max`). Then amend ADR-0006 (target slots, the `min` check), correct
  `target/minOccurs/004`, add an mc-memo case as an observed guard, and a fix ticket starts red
  from them.
