# F-35 — The `orders` mapping cannot hold "one single-value UDF"

- **Assumption** (ADR-0021 scenario table, `orders` row): the benchmark mapping has one single-value UDF.
- **How it fails**: ADR-0030 (2026-11-10) removes UDFs from milestone 1; `engine/udf-api` and
  `engine/udf` are not built and lowering refuses a UDF box. The row cannot be built.
- **Severity**: minor (the benchmark still exercises a calling function with a cost like a UDF call)
- **Evidence**: ADR-0030; ADR-0021 line 72; #181 grilling (owner, 2026-11-10).
- **Change made**: ADR-0021 gets a dated note: `orders` uses `FormatNum` on the amounts and
  `DateTrans` on a date, through `Lift`, instead of the UDF.
